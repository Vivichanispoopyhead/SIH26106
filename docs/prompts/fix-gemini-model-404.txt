1. Find available Gemini models

Run from the repository root:

cd /mnt/d/SIH/SIH26106

Load the local .env file:

set -a
source .env
set +a

Use the loaded key to list models that support generateContent:

curl -sG \
  'https://generativelanguage.googleapis.com/v1beta/models' \
  --data-urlencode "key=$GEMINI_API_KEY" \
  | jq -r '.models[] | select(.supportedGenerationMethods[]? == "generateContent") | .name'

Choose one of the returned model names. The output may contain a value such
as:

gemini-2.5-flash

Use the model name after models/. Do not add models/ unless the provider
configuration specifically requires it.

6. If the model-list command fails

The key may be:

- invalid
- revoked
- restricted
- associated with the wrong Google project
- missing access to the Gemini API

Since the previous key was exposed, revoke it and use a newly generated key
before continuing.

Never commit the real key or place it in:

- .env.example
- Git history
- frontend files
- backend source files
- screenshots
- chat messages
